The Problem

Traditional static computer networks rely on rigid, pre-configured forwarding tables and lack real-time awareness of application states. When a physical link is severed or a server experiences sudden traffic spikes, static networks drop packets or cause application timeouts.

Our Dynamic SDN Solution

We designed, implemented, and evaluated an Application-Aware Dynamic Software-Defined Network. By coupling low-level multi-threaded Python TCP sockets with an OpenFlow 1.3 controller (os-ken), the network automatically reroutes around failed links in < 2.5ms (0% packet loss) and redirects overloaded server traffic via wire-speed NAT flow modifications.

Viva Presentation Quick Reference

Separation of Planes: Data Plane runs on 3 Mininet Open vSwitch instances (s1 Core, s2 Server, s3 Client) connected over OpenFlow 1.3 to centralized os-ken on TCP port 6653.

Loop Guard Isolation: Redundant link s2:4 <-> s3:5 is guarded by Priority-5 drop flows to prevent broadcast storms while on standby.

EventOFPPortStatus Handler: Physical link drop is detected asynchronously. The controller installs Priority-20 flow mods into s2 and s3, routing traffic over the backup corridor in < 2.5ms with 0% loss.

Northbound REST & Hardware NAT: Server 1 monitors concurrent sockets. When active conns ≥ 2, it POSTs to /api/overload. Switch s1 installs bidirectional Priority-20 NAT rules redirecting requests to replica server2 (10.0.0.12).
